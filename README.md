# 📋 Замеры — Telegram бот + веб-панель

Система приёма заявок на замер через Telegram Mini App с хранением в PostgreSQL и веб-панелью для просмотра.

## Что умеет

- **Mini App форма** прямо в боте — вместо Google Forms
- **Красивые сообщения** в группу с кнопками смены статуса
- **Веб-панель** с фильтрами, поиском и историей изменений
- **PostgreSQL** база с полным логированием
- **Деплой на Railway** за 10 минут

## Деплой на Railway — пошагово

### Шаг 1 — Создай бота у @BotFather

1. Открой [@BotFather](https://t.me/BotFather) в Telegram
2. `/newbot` → введи имя и username
3. Скопируй **BOT_TOKEN**
4. Потом вернёшься сюда чтобы добавить Mini App

### Шаг 2 — Создай проект на Railway

1. Зайди на [railway.app](https://railway.app) → **New Project**
2. **Deploy from GitHub repo** → подключи репозиторий с этим кодом
   - Или: **Deploy from template** → пусто, потом `railway up` из CLI

### Шаг 3 — Добавь PostgreSQL

В проекте Railway:
1. Нажми **+ New** → **Database** → **PostgreSQL**
2. Railway автоматически добавит `DATABASE_URL` в переменные окружения

### Шаг 4 — Переменные окружения

В Railway → твой сервис → **Variables** добавь:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `GROUP_CHAT_ID` | ID группы (как получить — см. ниже) |
| `WEBAPP_URL` | URL твоего приложения на Railway (см. Settings → Domain) |
| `ADMIN_PASSWORD` | пароль для входа в панель |
| `ADMIN_TG_IDS` | Telegram ID администраторов через запятую. Нужны для первичного одобрения сотрудников |
| `SESSION_SECRET` | любая случайная строка (32+ символа) |
| `NODE_ENV` | `production` |

> `DATABASE_URL` Railway добавит сам при создании PostgreSQL сервиса.

#### Как узнать GROUP_CHAT_ID

1. Добавь бота в группу
2. Напиши любое сообщение в группе
3. Открой: `https://api.telegram.org/bot<BOT_TOKEN>/getUpdates`
4. Найди `"chat":{"id":` — это и есть GROUP_CHAT_ID (отрицательное число)

### Шаг 5 — Подключи Mini App к боту

После деплоя, когда у тебя есть URL вида `https://zamery-xxx.railway.app`:

1. В @BotFather → `/newapp` или `/mybots` → выбери бота → **Bot Settings** → **Menu Button**
2. Или: `/setmenubutton` → укажи URL: `https://zamery-xxx.railway.app/form`
3. Название кнопки: `📋 Новая заявка`

### Шаг 6 — Проверка

- Открой бота → нажми `/start` → появится кнопка **📋 Новая заявка**
- Заполни форму → в группе придёт красивое сообщение с кнопками
- Зайди на `https://zamery-xxx.railway.app/admin` → введи пароль → увидишь заявку

## Кнопки в группе

Когда приходит заявка, под сообщением есть кнопки:
- **🔧 Взять в работу** — меняет статус, кнопки обновляются
- **✅ Готово** — закрывает заявку
- **❌ Отменить** — отмена

Всё логируется с именем пользователя кто нажал.

## Локальная разработка

### Крупные выписки ЕГРН

Бот отправляет PDF/ZIP до 50 МиБ обычным документом. Более крупные файлы (до 2 ГиБ минус 1 байт) сохраняются целиком в приватном S3-хранилище, а PostgreSQL хранит только сведения о файле и доставке. В чат выписок, заказавшему сотруднику и получателям заявки приходит кнопка скачивания оригинала. Если Telegram отклоняет обычное вложение как слишком большое, бот также переключается на ссылку. Для работы нужен Node.js 20 или новее.

Ответ ARM РУС разбирается потоком: base64 не собирается в большую строку, PDF/ZIP временно записывается в закрытую папку со случайным именем и затем переносится в хранилище с проверкой размера и SHA-256. PDF из ZIP извлекаются последовательно с проверкой размера и CRC32. Повторяющиеся оригиналы из исторических статусов исключаются; файлы других заказов не доставляются. Временные файлы удаляются при успехе, ошибке или отмене; после аварийного перезапуска остатки старше суток удаляются при следующем опросе. При сетевом обрыве выполняется до трёх попыток чтения того же заказа в пределах общего срока 20 минут, без нового платного заказа. Служебные метаданные ограничены 2 МиБ, суммарный временный объём — двумя предельными файлами. Если PDF из ZIP нельзя безопасно извлечь, сохраняется исходный архив.

Ссылка подписана для конкретного файла и действует 7 дней. Кнопка «Обновить ссылку» создаёт новую ссылку на сохранённый оригинал после проверки доступа сотрудника; повторный заказ в ARM РУС не требуется. Перезапуск приложения не удаляет оригинал. Повтор уведомления использует сохранённые подтверждения доставки получателям.

Используются существующие `WEBAPP_URL` (HTTPS-адрес приложения) и `BOT_TOKEN`; токен бота и ключ ARM РУС в ссылку не попадают. При необходимости отдельный ключ подписи можно задать серверной переменной `EGRN_DOWNLOAD_SECRET` длиной от 32 байт. Ключи нельзя коммитить в репозиторий. Скачивание выполняется потоком, без сборки полного файла в памяти веб-сервера.

Настройки S3 задаются серверными переменными `EGRN_S3_ENDPOINT`, `EGRN_S3_BUCKET`, `EGRN_S3_ACCESS_KEY_ID`, `EGRN_S3_SECRET_ACCESS_KEY`, `EGRN_S3_REGION`. В Railway используются ссылки на переменные приватного bucket `egrn-files`, например `EGRN_S3_BUCKET=${{egrn-files.BUCKET}}`. Регион, endpoint и ключи также передаются ссылками; открывать или копировать их значения для подключения не требуется. Bucket использует virtual-hosted URLs и не предоставляет публичного доступа.

При полном наборе настроек новые оригиналы записываются в S3; частичная конфигурация останавливает сохранение без перехода на базу. Без настроек S3 сохраняется прежний режим PostgreSQL с блоками по 1 МиБ для локальной разработки и совместимости. Старые оригиналы в PostgreSQL продолжают скачиваться и не удаляются. Использование файлового хранилища учитывается в тарифе [Railway Buckets](https://docs.railway.com/storage-buckets/billing).

При первом запуске этой версии готовые выписки за последние 30 дней, доставка которых была остановлена ограничениями 50 или 200 МиБ, возвращаются в очередь доставки. Новые платные заказы при этом не создаются. Миграция ограничения размера сохраняет уже полученные оригиналы и действующие ссылки. Лимиты загрузки материалов и разметки PDF в форме аудитора этим изменением не меняются.

Для поддержки: `/egrn_retry номер_заказа` в личке бота повторяет доставку уже готового недоставленного заказа за последние 30 дней. Доступ имеют только одобренные сотрудники и администраторы. Команда не создаёт заказ у поставщика; сохранённый оригинал и подтверждённые доставки используются повторно. В журнале ошибок доставки доступны только безопасные поля этапа, кода и имени ограничения базы, без исходных ответов и секретов. Срок сетевого запроса не прерывает сохранение уже полностью полученного локального файла.

```bash
# Установка зависимостей
npm install

# Скопируй и заполни переменные
cp .env.example .env

# Создай таблицы (нужен DATABASE_URL в .env)
npm run migrate

# Запуск (polling режим, без webhook)
npm run dev
```

## Веб-панель

URL: `https://your-app.railway.app/admin`

- **Дашборд** — счётчики по статусам
- **Таблица** — все заявки с фильтром по статусу и поиском
- **Детальная страница** — полные данные + смена статуса + история изменений
- **Фильтры**: Все / Новые / В работе / Выполнены / Отменены
- **Поиск**: по адресу, имени, контактам

## База данных

### Таблица `orders`

| Поле | Тип | Описание |
|---|---|---|
| id | serial | Номер заявки |
| address | text | Адрес объекта |
| owner_name | text | Чей объект |
| object_type | text | Тип объекта |
| object_name | text | Название (опц.) |
| has_video | boolean | Нужно видео |
| zones_info | text | Инфо о зонах |
| deadline | date | Крайний срок |
| contacts | text | Контакты |
| status | text | new/in_progress/done/cancelled |
| telegram_msg_id | bigint | ID сообщения в группе |
| submitted_by | bigint | Telegram ID кто подал |
| created_at | timestamptz | Время создания |

### Таблица `logs`

Каждое изменение статуса + создание заявки логируется с временем, актором и деталями.
